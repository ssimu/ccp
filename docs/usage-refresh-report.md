# 사용량 갱신·롤오버 작업 보고

2026-11-13. 공개 저장소용 합성 데이터만 사용했다. 커밋·푸시·다른 Mac 접속·실제 사용자 설정 변경·실제 계정 `/usage` 실행은 하지 않았다.

## 1. 지난 리셋 롤오버

- `ccp_usage.normalize()`와 `roll_window()`로 공통 처리한다. 주간 7일, 세션 5시간, 모델 7일을 반복해서 다음 창으로 넘기고 사용률을 0%로 추정한다.
- `/usage`, 캐시 파일, 계정 일치 스냅숏 모두 같은 규칙을 적용한다. 상태줄의 직접 전달된 주간·세션도 같은 `roll_window()`를 쓴다. 메뉴의 추천·그래프·표·타임라인은 보정된 값을 받는다. `fleet-pick`도 기존 `menu()`/`parse()` 경로에서 보정된 값을 받는다.
- 연도 없는 리셋은 연말 양방향 경계를 처리한다. 세션이 없거나 null이면 계속 미보고이며, 관측 시각은 캐시를 다시 저장해도 보존한다.
- `리셋 지남 · 추정 · cache MM/DD HH:MM`을 4개 언어로 표시한다. 새 창에서 실제 사용한 양은 다시 조회하기 전에는 알 수 없다.

## 2. Fable 자체 리셋

- `Current week (<모델>)`와 `weekly_scoped.resets_at`을 저장한다. 상태줄 눈금·리셋, 그래프 눈금, 추천 페이스가 이 시각을 사용한다. 주간과 다른 리셋은 메뉴에 별도 안내한다.
- TSV 12칸은 유지한다. 메모의 `ccp:v1:` JSON 접미사에 절대 시각·관측 시각·추정 창을 저장하고 렌더러가 이를 숨긴다. 칸을 늘리지 않아 Codex의 기존 행 계약은 바꾸지 않았다.
- 옛 캐시는 파일 수정 시각+남은 분으로 복원하며, 모델 리셋이 없으면 주간을 대신 쓴다. 최신 스냅숏에 모델 정보가 없으면 모델 정보가 있는 캐시 중 최신 값을 선택한다.

## 3. 주기 갱신

- `ccp-usage-refresh`: 로그인된 기본/추가 프로필을 순차 조회한다. 최근 10분 성공은 생략하고, 프로필당 90초·전체 600초 예산을 적용한다. 키체인 검사에도 남은 예산을 전달한다.
- 전체 flock과 기존 프로필 flock을 함께 사용한다. 최근 시도 시각도 순서에 반영해 실패 프로필이 뒤쪽 프로필을 계속 밀어내지 않게 했다. 실패는 정상 캐시를 덮어쓰지 않는다.
- `install.sh`가 명령 링크와 GUI Aqua LaunchAgent를 준비한다. 주기는 900초, 로그인 시에도 실행한다. `--no-usage-refresh`와 표식 파일로 끌 수 있다. SSH 설치는 plist만 작성하고 bootstrap하지 않는다.
- `start_refresh()`는 등록된 GUI 작업에 `launchctl kickstart`를 보낸다. `-k` 없이 실행하므로 실행 중인 작업을 중단하지 않는다. 실제 작업 소유권은 launchd에 있다. 미설치/실패 시 기존 분리 자식 방식은 보조 경로로 남긴다.
- 이중 fork/nohup을 추가하지 않았다. 관리 터미널의 자식 일괄 정리를 피한다는 근거가 없으며, GUI 작업으로 요청을 넘기는 경로가 명확하다. **실제 hc에서 부모 종료 후 생존하는지는 이번 작업에서 실측하지 않았다.**

## 4. 낡음 표시

- 기존 30분 stale 기준을 유지했다. 15분 타이머의 정상 갱신 한 번을 놓친 정도부터 구분하기에 맞고, 주간 사용량에 지나치게 짧은 기준을 적용하지 않는다.
- 막대·수치·리셋 타임라인을 흐리게 하고 `stale`과 조회 시각을 보인다. 추정값도 흐리게 표시한다. 확인된 최신 후보를 우선 추천하며, 없으면 표시를 유지한 채 대체 후보를 추천한다.
- 좁은 화면에서는 안내를 줄바꿈하고, 높이가 부족하면 행간 공백을 줄인다. 80×24에서 낡은 계정 6개와 독립 Fable 리셋까지 시험했다.
- 상태줄은 낡은 모델에 조회 시각과 `~`, 추정 모델에는 추정 안내와 조회 시각을 붙인다. README 한국어 본문과 en/ja/zh 요약, 상태줄 설정 예시를 갱신했다.

## 배치 후 마스터가 할 일

승인한 수정본을 각 Mac의 저장소에 배치한 다음 **각 Mac의 데스크톱 터미널**에서 실행한다. 이번 작업에서는 배치/설치를 실행하지 않았다.

```zsh
cd ~/projects/ccp
./install.sh
source ~/.zshrc
launchctl print "gui/$(id -u)/local.ccp.usage-refresh"
launchctl kickstart "gui/$(id -u)/local.ccp.usage-refresh"
ccp-usage
```

완료 후 각 Mac에서 두 번 이상의 주기 동안 조회 시각이 전진하는지, 잠긴 키체인 맥락에서 조회를 생략하는지, hc의 짧은 부모 종료에도 GUI 작업이 계속되는지 확인한다. 프로필 이름은 각 Mac의 실제 디렉터리에서 찾으므로 통일할 필요가 없다.
끄기·재개·제거 명령은 [README](../README.md#사용량의-낡음리셋주기-갱신)에 있다. 로그아웃·절전·네트워크 실패 중에는 신선도를 보장할 수 없다.

## 시험과 미리보기

기준선은 Python 193 통과·1 건너뜀. 최종 `python3 -m pytest tests -q -rs`는 **234 통과·1 건너뜀**, `zsh tests/test_ccp_zsh.sh`는 **92 통과·0 실패**다. Python 시험 41개를 추가했으며 기존 시험 수를 줄이지 않았다. 건너뜀은 기존과 같은 Python 3.9의 `tomllib` 부재다. `git diff --check`, 설치 스크립트와 생성된 zsh 사전의 문법 검사도 통과했다. 모든 신규 실행 시험은 가짜 HOME과 합성 캐시/가짜 CLI를 사용했다. 전체 시험도 별도 가짜 HOME에서 실행했다.
키체인 잠김은 `security`의 `User interaction is not allowed` 응답을 합성했으며 실제 키체인을 잠그지 않았다. 시간 상한은 가짜 시계/timeout 전달로 검사했고 프로세스를 강제로 종료하지 않았다.

별도 읽기 전용 리뷰에서 발견한 실패 프로필 순서, 모델 캐시 선택, 추정 시각 누락, 좁은 화면, 키체인 시간 예산 문제를 회귀 시험과 함께 수정했다.

미리보기 재현: `python3 tests/preview_usage.py`. HEAD의 원래 코드와 작업트리를 임시 디렉터리에서 실행하며 네트워크/실제 계정 접근 없이 비교한다. 아래는 ANSI 색을 제거한 글 화면이다. 실제 터미널의 흐림 처리는 합성 TTY 시험에서 확인했다.
